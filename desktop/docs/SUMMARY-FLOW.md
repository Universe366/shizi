# 字幕总结全流程（0.117.0）

> 本文记录当前唯一总结链路：原总结提示词 + 对话式联网工具循环。
> 旧的前置核对流程已从生产路径删除。

## 1. 总览

```text
总结面板
  → ai:summarize
  → summarizeChat
  → buildSummaryChatPrompt（原总结模板 + 术语表 + 格式规则 + 视频元信息）
  → 分段判断（summarySegments）
      ├─ 1 段：直接总结
      └─ N 段：逐段提取 → 最终合并（合并阶段联网）
  → chat() 工具循环
      ├─ app__web_search
      ├─ app__web_fetch
      └─ app__read_tool_output
  → 保存总结 + 来源
```

## 2. 调用链

| 层 | 文件 | 职责 |
|---|---|---|
| 界面 | `SummaryPanel.tsx` | 读取字幕、发送请求、流式展示、联网开关 |
| IPC | `ipc/media.ts` | 校验、任务中心、取消、保存 |
| 总结编排 | `summaryChat.ts` | 分段、逐段总结、最终合并 |
| 提示词 | `ai.ts` | 模板、术语表、格式规则、视频元信息 |
| 对话/工具 | `chat.ts` | 平台解析、工具循环、搜索/读取/引用 |
| 搜索 | `web/retrieve.ts`、`web/fetch.ts` | 检索、排序、读正文、缓存 |

## 3. 分段规则

设置项：`search.summarySegments`

- `0`：自动
  - 字幕 ≤ 20000 字符：不分段
  - 超过：`ceil(字符数 / 18000)`，限制在 2–8 段
- `1`：强制不分段
- `2–20`：固定段数，按字符数均分，保留每条字幕完整

分段阶段：

- 每段单独调用一次对话式总结
- 分段阶段 **不联网**，避免每段都发起工具循环
- 分段结果不直接展示，只作为最终合并的输入

最终合并：

- 输入是各段总结
- **恢复联网**，模型可以搜索/读网页
- 最终结果流式输出到界面

## 4. 系统提示词

`buildSummaryChatPrompt(info)` 组装：

```text
<当前选中的总结模板>

<术语表：用户配置的 from → to>

<SUMMARY_FORMAT_RULES>
```

### 4.1 总结模板

默认模板：

```text
整理这期视频的内容（可以用表格、代码块、高亮块、引用、超链接、公式、图片等飞书支持的格式输出，可以加上一些图标增加可读性）
```

用户可在设置中切换「默认 / 精简 / 详细 / 自定义」模板。

### 4.2 术语表

只有用户配置了术语时才出现：

```text
术语表（输出时统一使用以下写法）：
- 原词 → 统一写法（备注）
```

### 4.3 格式规则（完整）

```text
【输出风格：做成一份信息密度高的图文笔记，不要平铺直叙的流水账】

飞书文档能渲染丰富结构，请**主动使用**，不要只用「标题 + 段落」：

1. **先给一句话结论**，紧接一个「速览」表格（3~6 行），让读者 10 秒抓住重点。
2. **该用表格就用表格** —— 对比、参数、时间线、优劣、步骤一律用管道表格，
   不要写成句子。必须有表头与 `---` 分隔行。
3. **引用块（行首 `> `）用来强调关键判断或原话**，例如 `> **结论**：…`。
4. **代码块**（三个反引号 + 语言）用于命令、配置、代码、数据样例。
5. **超链接**写成 `[文字](https://…)`。**只链接字幕里明确出现过、或你确信真实存在的 URL**，绝对不要编造。
6. **公式**用 LaTeX：行内 `$…$`、块级 `$$…$$`。
7. **任务列表** `- [ ]` / `- [x]` 用于待办、检查项、可执行建议。
8. **分割线** `---` 用于分节。
9. **emoji 做小标题前缀**提升可读性（如 `## 🎯 核心结论`），但不要每行都加。
10. **图片无法通过文本携带**。某个位置适合配图时，用一行 `> 🖼️ 建议配图：<放什么图>` 占位，不要输出假的图片语法。

【硬性要求】
· 内容必须**全部来自字幕**（以及下方给出的简介/评论/外部补充），不要引入字幕里没有的信息。
· **不要输出**内嵌 HTML、脚注、自定义容器语法、base64 图片。
· 标题最多三级（`#` / `##` / `###`），不要跳级。

【详细程度：宁可详细，不要简略】
· 这是一份**完整的观看笔记**，不是摘要提纲，请充分展开。
· 每个要点都要写清「是什么 + 为什么 + 怎么做/结论」，不要只写一句短语。
· 视频里出现的**具体数字、名称、命令、步骤、参数、结论**都要保留；有流程就逐步列出，有对比就做成表格，有坑就写清现象与原因。
· 按内容自然分节，不要为了短而合并章节；长视频写长一些是正常的。
· 唯一要避免的是**重复与灌水** —— 不要为了凑长度而复述同一件事。
```

### 4.4 联网工具说明（由 chat 追加）

```text
本轮已开启联网：需要外部事实时调用 web_search（可以多次、换关键词）；
需要核对具体页面时用 web_fetch 打开搜索结果里的链接（最多 3 次）。
引用时把结果里的 index 写成 [n]，回答末尾用「参考：」列出实际用到的链接，不要编造编号。
```

如果已有联网参考（webBlock），再追加：

```text
引用外部事实时在句末用 [n] 标注来源；回答末尾用「参考：」列出实际用到的链接（只列用到的），不要编造编号。
```

## 5. 用户提示词

### 5.1 视频元信息

```text
视频标题：<title>
UP 主：<owner>
视频时长：<h:mm:ss>
链接：<url>
视频简介：<desc，最多 2000 字，可在设置关闭>
官方分段：<官方章节文本，有则带>
```

### 5.2 直接总结（不分段）

```text
<视频元信息>

请基于上面的字幕写一份完整总结，严格按系统提示里的格式规则输出；不要写开场白或“根据字幕”这类过程说明。
需要外部事实时，可以调用联网搜索/读取网页；用到外部资料时用 [n] 标注来源。
```

`chat()` 会在系统消息之后、这条用户消息之前插入：

```text
以下是当前视频的字幕（带时间戳），请作为回答依据：

<字幕全文>
```

### 5.3 分段提取

每段用户消息：

```text
<视频元信息>

请基于上面的字幕写一份完整总结，严格按系统提示里的格式规则输出；不要写开场白或“根据字幕”这类过程说明。
需要外部事实时，可以调用联网搜索/读取网页；用到外部资料时用 [n] 标注来源。

这是第 i/N 段字幕。只整理这一段，做成结构化笔记；不要写“本段/接下来”这类过渡语，也不要臆测其它段落。
```

分段阶段 `web=false`，不调用搜索工具。

### 5.4 最终合并

```text
<视频元信息>

请基于上面的字幕写一份完整总结，严格按系统提示里的格式规则输出；不要写开场白或“根据字幕”这类过程说明。
需要外部事实时，可以调用联网搜索/读取网页；用到外部资料时用 [n] 标注来源。

下面是同一视频的 N 段分段总结。请合并成一份最终总结，覆盖全片、去重、保留数字/时间/步骤；段落之间冲突时以字幕内容为准。需要外部事实时可以联网搜索/读取网页，并在用到时标注来源。

【第 1 段】
...
【第 2 段】
...
```

合并阶段 `includeTranscript=false`，不再附完整字幕；联网工具开启。

## 6. 工具

### 6.1 app__web_search

```json
{
  "name": "app__web_search",
  "description": "搜索公开网页获取最新或外部事实。可以多次调用、换关键词；结果里的 index 可用于引用 [n]。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
        "description": "自包含的搜索词，不要用代词；需要时换语言或换关键词再搜一次"
      }
    },
    "required": ["query"]
  }
}
```

行为：

- 最多 5 次搜索
- 相同 query 命中缓存，不重复请求
- 结果数：`min(20, search.maxResults || 6)`
- 每条结果包含：index、title、url、site、date、excerpt（正文/摘要前 800 字）
- 读取正文篇数：`search.chatReadPages`（默认 2）
- index 对应最终 `[n]` 引用

### 6.2 app__web_fetch

```json
{
  "name": "app__web_fetch",
  "description": "打开一篇公开网页并读取正文。用于核对搜索结果里的具体链接；本机/内网地址会被拒绝。",
  "parameters": {
    "type": "object",
    "properties": {
      "url": { "type": "string", "description": "http/https 网页地址" }
    },
    "required": ["url"]
  }
}
```

行为：

- 最多 3 次读取
- 相同 URL 命中缓存
- 返回 JSON：url、title、chars、source、rendered/fallbackFrom、content
- 正文最多 3200 字符
- 走当前「网页读取」provider：Jina / 内置抓取 / 浏览器渲染 / 第三方
- 失败会回退到内置抓取（方案内已实现）

### 6.3 app__read_tool_output

当工具结果超过上下文上限时，结果末尾给出 id 和 offset；模型可分批读取完整输出。

```json
{
  "name": "app__read_tool_output",
  "parameters": {
    "type": "object",
    "properties": {
      "id": { "type": "string" },
      "offset": { "type": "number" }
    },
    "required": ["id"]
  }
}
```

## 7. 工具循环限制

| 项 | 值 |
|---|---|
| 最大轮次 | 联网时 10 轮 |
| 搜索次数 | 5 |
| 网页读取次数 | 3 |
| 单条工具结果内联 | 约 4000 字符，超出走 read_tool_output |
| 搜索缓存 | 按 query 缓存 |
| 网页缓存 | 按 URL 缓存 |
| 引用编号 | 搜索结果 index 全局递增，映射到 [n] |

## 8. 模型与平台

- 当前 `summarizeChat` 调用 `chat()`，使用 **chat 任务槽位**的平台/模型。
- 分段提取和最终合并使用同一个平台/模型。
- 旧总结的 `summary` 任务槽位不再用于这条链路。

## 9. 保存与展示

- 最终文本写入 `saveSummary`
- 来源保存为 `verification.sources`（只有来源，没有逐项判定）
- 界面展示：
  - 总结正文
  - 「外部资料」卡片（来源）
  - 耗时、token（如果事件带 usage）
- 历史总结的旧核对数据仍可展示

## 10. 已知限制

- 分段阶段不联网，只有最终合并联网
- 长视频分段会多次调用模型，耗时随段数增加
- 最终合并输入是分段总结，不是原始字幕
- 没有逐项支持/反驳报告
- 模型是否真正调用搜索取决于模型行为；状态栏会显示联网检索
