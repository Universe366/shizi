# 字幕总结全流程（0.136.0）

> 当前只有一条总结链路：原总结提示词 + 对话式联网工具循环。
> 不分段；旧的前置核对流程已从生产路径删除。

## 1. 总览

```text
总结面板
  → ai:summarize
  → summarizeChat
  → buildSummaryChatPrompt（原总结模板 + 术语表 + 格式规则 + 视频元信息）
  → chat() 工具循环
      ├─ app__web_search
      ├─ app__web_fetch
      └─ app__read_tool_output
  → 保存总结 + 来源
```

## 2. 调用链

| 层 | 文件 | 职责 |
|---|---|---|
| 界面 | `SummaryPanel.tsx` | 读取字幕、联网开关、流式展示、字数统计 |
| IPC | `ipc/media.ts` | 校验、任务中心、取消、保存 |
| 总结编排 | `summaryChat.ts` | 调用提示词与 chat 工具循环 |
| 提示词 | `ai.ts` | 模板、术语表、格式规则、视频元信息 |
| 对话/工具 | `chat.ts` | 平台解析、工具循环、搜索/读取/引用 |
| 搜索 | `web/retrieve.ts`、`web/fetch.ts` | 检索、排序、读正文、缓存 |

## 3. 系统提示词

`buildSummaryChatPrompt(info)` 组装：

```text
<当前选中的总结模板>

<术语表：用户配置的 from → to>

<总结格式规则>
```

「总结模板」和「总结格式规则」都可以在 **设置 → 提示词模板** 里查看和编辑：

- 模板：一句话主题，例如默认的「整理这期视频的内容…」
- 格式规则：完整的图文笔记规范，之前硬编码在代码里，现在单独暴露

### 3.1 总结模板

默认：

```text
整理这期视频的内容（可以用表格、代码块、高亮块、引用、超链接、公式、图片等飞书支持的格式输出，可以加上一些图标增加可读性）
```

用户可在设置中切换「默认 / 精简 / 详细 / 自定义」。

### 3.2 术语表

只有配置了术语才出现：

```text
术语表（输出时统一使用以下写法）：
- 原词 → 统一写法（备注）
```

### 3.3 格式规则（完整）

```text
【输出风格：做成一份信息密度高的图文笔记，不要平铺直叙的流水账】

飞书文档能渲染丰富结构，请**主动使用**，不要只用「标题 + 段落」：

1. **先给一句话结论**，紧接一个「速览」表格（3~6 行），让读者 10 秒抓住重点。
2. **该用表格就用表格** —— 对比、参数、时间线、优劣、步骤一律用管道表格，
   不要写成句子。必须有表头与 `---` 分隔行。
3. **引用块（行首 `> `）用来强调关键判断或原话**，例如 `> **结论**：…`。
4. **代码块**（三个反引号 + 语言）用于命令、配置、代码、数据样例。
5. **超链接**写成 `[文字](https://…)`。**只链接字幕里明确出现过、或你确信真实存在的 URL**，绝对不要编造。
6. **公式**用 LaTeX：行内 `$…$`、块级 `$$…$$`。
7. **任务列表** `- [ ]` / `- [x]` 用于待办、检查项、可执行建议。
8. **分割线** `---` 用于分节。
9. **emoji 做小标题前缀**提升可读性（如 `## 🎯 核心结论`），但不要每行都加。
10. **图片无法通过文本携带**。某个位置适合配图时，用一行 `> 🖼️ 建议配图：<放什么图>` 占位，不要输出假的图片语法。

【硬性要求】
· 内容必须**全部来自字幕**（以及下方给出的简介/评论/外部补充），不要引入字幕里没有的信息。
· **不要输出**内嵌 HTML、脚注、自定义容器语法、base64 图片。
· 标题最多三级（`#` / `##` / `###`），不要跳级。

【详细程度：宁可详细，不要简略】
· 这是一份**完整的观看笔记**，不是摘要提纲，请充分展开。
· 每个要点都要写清「是什么 + 为什么 + 怎么做/结论」，不要只写一句短语。
· 视频里出现的**具体数字、名称、命令、步骤、参数、结论**都要保留；有流程就逐步列出，有对比就做成表格，有坑就写清现象与原因。
· 按内容自然分节，不要为了短而合并章节；长视频写长一些是正常的。
· 唯一要避免的是**重复与灌水** —— 不要为了凑长度而复述同一件事。
```

### 3.4 联网工具说明（chat 追加）

```text
本轮已开启联网：需要外部事实时调用 web_search（可以多次、换关键词）；
需要核对具体页面时用 web_fetch 打开搜索结果里的链接（默认最多 3 次，可设置）。
引用时把结果里的 index 写成 [n]，回答末尾用「参考：」列出实际用到的链接，不要编造编号。
```

```text
视频标题：<title>

```

### 4.2 总结指令

```text
<视频元信息>

请基于上面的字幕写一份完整总结，严格按系统提示里的格式规则输出；不要写开场白或“根据字幕”这类过程说明。
尽量详细：每个主题至少展开 2–4 个具体要点，保留数字、时间、步骤、例子和结论，不要只写一句话概括。
需要外部事实时，可以调用联网搜索/读取网页；用到外部资料时用 [n] 标注来源。
```

`chat()` 会在系统消息之后、这条用户消息之前插入：

```text
以下是当前视频的字幕（带时间戳），请作为回答依据：

<字幕全文>
```

## 5. 工具

### 5.1 app__web_search

```json
{
  "name": "app__web_search",
  "description": "搜索公开网页获取最新或外部事实。可以多次调用、换关键词；结果里的 index 可用于引用 [n]。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
        "description": "自包含的搜索词，不要用代词；需要时换语言或换关键词再搜一次"
      }
    },
    "required": ["query"]
  }
}
```

行为：

- 默认最多 5 次搜索，可在设置调整（1–20）
- 相同 query 命中缓存
- 结果数：`min(20, search.maxResults || 6)`
- 每条结果：index、title、url、site、date、excerpt（前 800 字）
- 读取正文篇数：`search.chatReadPages`（默认 2）
- index 对应最终 `[n]`

### 5.2 app__web_fetch

```json
{
  "name": "app__web_fetch",
  "description": "打开一篇公开网页并读取正文。用于核对搜索结果里的具体链接；本机/内网地址会被拒绝。",
  "parameters": {
    "type": "object",
    "properties": {
      "url": { "type": "string", "description": "http/https 网页地址" }
    },
    "required": ["url"]
  }
}
```

行为：

- 默认最多 3 次读取，可在设置调整（1–10）
- 相同 URL 命中缓存
- 返回 JSON：url、title、chars、source、rendered/fallbackFrom、content
- 正文最多 3200 字符
- 走当前网页读取 provider（Jina / 内置抓取 / 浏览器渲染 / 第三方），失败会回退

### 5.3 app__read_tool_output

工具结果超过上下文上限时，用 id + offset 分批读取。

```json
{
  "name": "app__read_tool_output",
  "parameters": {
    "type": "object",
    "properties": {
      "id": { "type": "string" },
      "offset": { "type": "number" }
    },
    "required": ["id"]
  }
}
```

## 6. 工具循环限制

| 项 | 值 |
|---|---|
| 最大轮次 | 默认 10 轮，可在高级设置调整（1–20） |
| 搜索次数 | 默认 5 次，可在高级设置调整（1–20） |
| 网页读取次数 | 默认 3 次，可在高级设置调整（1–10） |
| 单条结果内联 | 约 4000 字符，超出走 read_tool_output |
| 搜索缓存 | 按 query |
| 网页缓存 | 按 URL |
| 引用编号 | 搜索结果 index 全局递增，映射到 [n] |

## 7. 搜索来源：谁在搜

`summarizeChat` 固定传 `web: true`，但最终由 `chat()` 决定走哪条路：

### 7.1 默认：使用应用内配置的搜索服务

条件：`preferModelWeb !== true`，或模型未声明 web 能力。

- 模型调用工具 `app__web_search`
- 工具内部调用 `retrieveEvidence`
- 使用设置里的搜索平台（Exa MCP / Jina / Tavily / Exa API / Firecrawl / Querit 等）
- 搜索结果的 `index` 作为工具结果返回给模型
- 模型在最终总结里用 `[n]` 引用
- 保存的「外部资料」就是这些工具返回的 references

所以：**默认情况下，网页是应用内搜索服务搜的，并且会作为工具结果进入模型上下文**。

### 7.2 可选：模型内置联网

条件：设置开启「优先使用模型内置联网」，且当前模型声明支持 web。

- `useBuiltinWeb = true`
- 不注册 `app__web_search`
- 由模型服务商自己搜索，应用拿不到完整的工具结果列表
- 「外部资料」可能为空或只有模型返回的来源
- 不经过应用的搜索平台设置

### 7.3 是否一定参与总结

不保证。

- 模型可以决定不调用 `web_search`
- 调用了也可以不采用结果
- 只有工具结果进入上下文，模型才可能使用
- 状态栏出现「联网检索 / 已找到 N 条」才说明工具真的跑了

## 8. 保存与展示

- 最终文本写入 `saveSummary`
- 来源保存为 `verification.sources`（只有来源，没有逐项判定）
- 界面展示：
  - 总结正文
  - 耗时 + 字数统计（同一行）
  - 「外部资料」卡片（可滚动，最多 240px 高，紧凑行距）
  - token（如果事件带 usage）
- 历史总结的旧核对数据仍可展示

## 9. 模型

当前 `summarizeChat` 调用 `chat()`，使用 **chat 任务槽位**的平台/模型，不再是旧的 summary 槽位。

## 10. 已知限制

- 长视频整段字幕一次交给模型，不分段
- 模型可能不调用搜索，或调用后不采用
- 没有逐项支持/反驳报告
- 搜索来源取决于「优先模型内置联网」设置
